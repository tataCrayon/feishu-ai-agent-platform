## 1. 背景

为什么需要做这个决策？当前的问题、约束、驱动力。**3-5 句，可量化就写数字**。

## 2. 决策考虑

- **触发因素**：什么事件/数据逼出了这个决策
- **约束条件**：时间、成本、技术栈、合规、不能动的既有资产

## 写作纪律

1. **一条决策一个文件**，编号三位递增，文件名 `NNN-kebab-case.md`。
2. **accepted 后不改原文**（笔误除外）：决策变化 → 新建 ADR 并在旧的状态行写 `被 ADR-YYY 取代`。
3. **不写实施手册**：MUST/SHOULD 级别的实现细节、落地 checklist、逐条验收，属于功能简报
   （`docs/features/`）与 spec（`docs/specs/`）。ADR 里写这些会与代码漂移，且没人回头读。
4. **不写变更记录**：什么时候改成什么样是 git log 的事。
5. **不写复盘表**：复盘就是新 ADR——「原预期 vs 实际」放进新 ADR 的背景，才算被读过。
6. **理由必须可验证**：第 3、4 节严禁只有结论，数字/实测/事故里至少给一个。
