## 一、背景与目标

> 1-2 段话：解决什么痛点？为什么现在做？AI 实现者读完应能复述「这事为谁、解决什么」。

## 二、用户操作时序 `[必填，先于需求分解]`

> **为什么放最前**：AI 天然「按功能找着测」，不会自发站在用户座位上想「用户看不看得到、
> 知不知道下一步做什么」。本节把视角钉死在用户身上，后续 R 需求与验收全部从这条时序派生。
>
> **写法**（三参考融合，见附录 A）：
> - 每条时序**单视角**（一个 actor 一张表；管理员/普通用户/审批人分开写）
> - 步骤用 **Given / When / Then**（Gherkin）：Given 铺情境不写交互，
>   When 写用户动作，Then 写用户可观察的结果
> - **Then 一律以 `[用户看到]` 开头**——钉死在可观察面（消息/卡片/回复/文档变化），
>   禁止写内部状态（数据库字段、进程内标志位）
> - 每步标注认知走查四问（见附录 B）覆盖情况：`#走查②③` —— 该步设计是否回答了
>   「入口可见吗」「能把入口和目标对上吗」；答不上来的步骤就是设计缺口
> - 参考故事映射（Patton）：多角色需求先画「用户活动 → 步骤」骨干，R 需求挂在骨干上

### 时序 1：主流程（happy path）

```gherkin
actor: <角色，如 L2 管理员>
goal: <该角色要在本次交互中达成什么>

场景: <一句话概括>

1. Given <用户所处的初始情境，不写系统内部>
   When  <用户做一个动作>
   Then  [用户看到] <可观察结果：收到什么消息/卡片/回复，界面上什么变了>  #走查①④

2. When  <下一个用户动作>
   Then  [用户看到] <…>  #走查②③
```

### 时序 2+：异常/边界流（每条一个场景，至少覆盖：权限不足 / 输入不合法 / 服务不可用）

```gherkin
场景: <异常场景名>
1. Given <异常前置>
   When  <用户动作>
   Then  [用户看到] <明确的失败提示与下一步指引，不允许静默无响应>  #走查④
```

## 四、验收流程约定

> AI 验收 = 时序走查 + AC 断言两层，缺一不算完成：

1. **时序走查**（对第二节逐场景）：AI 能注入/驱动的步骤（消息管线、卡片 payload、
   回复文本）逐条真实执行并断言 `[用户看到]` 的内容；AI 无法操作真机的步骤
   （飞书客户端点按钮、看渲染）输出「人工走查清单」交用户，单条 ≤2 分钟。
2. **AC 断言**（对第三节）：`python app/eval/verify_spec.py [--with-llm]` 或等效脚本逐条输出
   PASS/FAIL/SKIP + 证据；任一 FAIL 修复后重跑全套，不接受部分通过即交付。
3. 走查与 AC 结果合并出报告：先贴用户时序走查表（用户视角），再贴 AC 对照表（系统视角）。

## 附录 A：方法论文献（写时序前速读）

| 来源 | 用在哪 | 核心规则 |
|------|--------|---------|
| Gherkin / BDD（cucumber.io/docs/gherkin/reference） | 时序步骤格式 | Given 情境 / When 动作 / Then 可观察结果；「忍住别查数据库」——Then 断言面向用户的输出，不查内部状态 |
| 认知走查（nngroup.com/articles/cognitive-walkthroughs） | 每步自查四问 | ①用户会想做这步吗 ②看得到入口吗 ③能把入口和目标对上吗 ④做完看得到进展吗；任一「不会/看不到」即设计缺口 |
| 用户旅程图（nngroup.com/articles/journey-mapping-101） | actor 与场景组织 | 每图单 actor 单视角；按阶段组织动作；解决「各角色只盯自己那段、没人拥有完整体验」的碎片化问题 |
| 用户故事映射（Jeff Patton, User Story Mapping） | R 需求挂骨干 | 先画「用户活动→步骤」骨干，功能挂骨干上——防止需求清单脱离用户时序变成功能堆砌 |

## 附录 B：认知走查四问速查卡

对时序中**每一步**依次回答（新用户座位，不是开发者座位）：

| # | 问题 | 答不上来时查什么 |
|---|------|----------------|
| ① | 用户会想达成这个结果吗？ | 时序 goal 是否真实、步骤顺序是否符合用户心智 |
| ② | 用户看得到正确的操作入口吗？ | 输出物清单：该步骤有没有对应的可见形态 |
| ③ | 用户能把入口和他的目标对上号吗？ | 文案/按钮语义是否自解释（不靠口头约定） |
| ④ | 做完这步，用户看得到进展了吗？ | Then 是否写明反馈；无反馈 = 用户不知道下一步 |
