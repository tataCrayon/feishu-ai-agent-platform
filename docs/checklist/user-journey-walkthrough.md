# 用户时序走查清单（每做一个面向用户的功能填一次）

> **用途**：验收的「用户座位」层，与 spec 的 AC 断言（系统座位）互补。
> 治的病：AI 按功能找着测，不验证「用户看不看得到入口、知不知道下一步」。
>
> **两层分工**：AI 走查 = 消息管线可注入、卡片 payload 可断言的步骤（AI 真实执行 + 贴证据）；
> 人工走查 = 要真机操作的步骤（飞书客户端点按钮、看渲染），交用户，单条 ≤2 分钟。

## 认知走查四问（对时序每一步依次问）

| # | 问题 | 答不上来时查什么 |
|---|------|----------------|
| ① | 用户会想达成这个结果吗？ | 时序 goal 是否真实、步骤顺序是否符合用户心智 |
| ② | 用户看得到正确的操作入口吗？ | 输出物清单：这一步有没有对应的可见形态 |
| ③ | 用户能把入口和他的目标对上号吗？ | 文案/按钮语义是否自解释（不靠口头约定） |
| ④ | 做完这步，用户看得到进展了吗？ | Then 是否写明反馈；无反馈 = 用户不知道下一步 |

方法出处：Gherkin 三段式（Then 断言面向用户输出，不查内部状态）+ NN/g 认知走查 + 用户旅程单视角原则。
完整方法论见 `docs/specs/_template.md` 附录 A。

**填写纪律**

- 任一问为 ❌ → 记为**设计缺口**（不是测试问题）：回 spec 补时序或改输出物，修完重走查。
- `[用户看到]` 断言必须贴证据（回复文本摘录 / 卡片 payload / 日志行），不接受「应该会」。
