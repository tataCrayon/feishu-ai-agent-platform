# 一致性判定（单一事实源）

AI 辅助生成的 PRD 最常见的病是「同一件事写了两遍、两遍不一样」。你的任务是**找出来并指出两处分别在哪**。

## 1. 术语：一个东西只能有一个名字

判据（任一命中即为问题）：

- 同义异名：`HKDAP` / `HKDAP-ETH`、`钱包归属类型` / `钱包归属方`、`赎回确认` / `赎回到账`。
- 大小写/中英混写：`Webportal` / `webportal`、`RWA Token` / `RWA代币`。
- 缩写未定义：正文首次出现即用的缩写，全文没有解释（`KYT`、`TMD`、`FUIDL`）。
- 同一概念在两处用了不同限定词：`付款账户` vs `付款 VA 账户`（能否混用要能判断）。

输出必须给出：`A 处原文（章节）` 与 `B 处原文（章节）`，并建议统一成哪个。

## 2. 枚举：每个枚举必须穷举且有默认值

- 正文提到的取值，字段表/枚举表里必须有（「全部兑换」按钮、`HKDAP-ETH`）。
- 枚举表里的取值，正文流程里必须有落脚点（定义了却从不出现的状态 = 死值）。
- 默认值、空值语义、未知值怎么处理，三者缺一即问题。
- 大小写/下划线不一致的枚举值算**两个不同值**（`order_status` vs `orderStatus`）。

## 3. 状态机：集合 ↔ 转移 ↔ 触发者

- **状态集合完整**：正文提到的每个状态（含终止态）必须在枚举里。孤儿状态（`已撤单` 只在一处出现）= 阻断。
- **转移完整**：每个状态要有进入条件和离开条件；终态要写清「能不能回来」。
- **触发者明确**：谁把它改到下一个状态（客户/中台/系统/外部上手），不能含糊成「系统处理」。
- **状态与字段一致**：状态描述里说的资金/持仓动作，必须与字段表/流程描述一致（例如「资金冻结中」vs「已解冻」）。
- **跨文档映射**：对客状态与中台状态是两套时，必须有一张映射表；缺映射 = 阻断。

## 4. 数量与集合

- 「共 N 个」与实列条数必须相等（机械可判，逐个数）。
- 集合差集：文中两处列同类事物时取差集（支持链 vs 必须校验的链、可导出状态 vs 实际枚举）。
- 区间边界：`≥ 50 万` / `> 50 万`、含/不含端点必须唯一。

## 5. 单一事实源

同一规则只允许有一处权威表述。发现重复表述时：

- 两处一致 → 建议删一处，或标注「以第 X 节为准」；
- 两处不一致 → **阻断**，指出两处并让人选。

典型：流程章节的「中台手动受理」与另一章节的「经内部复核后自动冻结」并存。

## 输出格式（每条对齐 prd-review 的约定）

```
kind: 术语 / 枚举 / 状态机 / 一致性
title: ≤30 字，说清「哪两处不一致」
quote: PRD 原文逐字引用（≤60 字）
section: 章节号或标题
issue: 为什么必须改（1~2 句）
suggestion: 具体怎么改（可直接抄进 PRD）
block_id: 引文所在块
```

一条只报一处问题。同一处有多个维度的问题时，报最具体的那条。
