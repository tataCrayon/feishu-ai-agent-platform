# 可执行性判定

判据：开发照着写，能不能一行不漏地写完。写不下去的地方，就是这份 PRD 的缺口。

## 1. 流程可执行

每一条流程必须同时有：**触发者 / 输入 / 输出 / 失败态**。

- 触发者含糊（「系统处理」「后台同步」）→ 缺失定义。
- 出现但全文没定义的动作（「经内部复核通过」「风控校验」）→ 阻断。
- 流程之间有先后依赖却没写（先上手确认成交，还是先中台确认成交）→ 阻断。
- 线上操作应写清是**手动**还是**自动**：写成「系统确认结算」但实际操作是运营点按钮，属于误导。

## 2. 字段与精度

每个字段必须给全七项，缺一即缺失定义：

`类型 / 精度（小数位）/ 单位或币种 / 必填与否 / 来源（谁写入）/ 脱敏要求 / 空值展示`

重点检查：

- 法币与虚拟币精度分别写死（法币 2 位 ≠ 虚拟币读币种配置）；精度配置存在哪个字段要写明。
- 金额类字段要写「含不含手续费」「四舍五入还是截断」。
- 时间字段要写时区（HKT / UTC）与格式。
- 同一字段在不同页面展示口径不同（列表截断 + Hover 全文 vs 详情完整）要明确。

## 3. 边界与并发

| 检查点 | 问什么 |
|---|---|
| 空值/极值 | 字段为空、金额为 0、超过上限时怎么表现 |
| 重复提交 | 幂等键是什么；重复提交弹什么、报什么错码 |
| 并发 | 同一账户并发下单，冻结的是哪个维度（账户 / 识别码 / 钱包地址）；冻结粒度必须在全文唯一 |
| 部分成功 | 批量操作中一条失败，其他条是否回滚 |
| 超时 | 外部依赖超时后的订单状态、是否自动重试、重试几次 |
| 回滚/撤销 | 什么状态下可撤、谁撤、冻结怎么退、已扣的资金怎么原路退回 |

**冻结粒度**这类问题一旦全文出现两种说法（「可用余额」/「对应钱包地址下」/「按识别码绑定」），直接判阻断——它决定并发安全。

## 4. 权限与审计

- 每个操作写清：谁能做（角色 + 判定依据）、越权时的表现（隐藏 / 灰置 / 报错）。
- 「授权人」「操作人」「发起人」这类角色必须写清**取数来源**，否则前端无处可取。
- 敏感操作要有留痕要求（谁、何时、改了什么、改前是什么）。
- 客户端与中台权限边界要分开写（客户能撤单吗？客服能代撤吗？）。

## 输出格式

```
kind: 缺失定义 / 边界缺失 / 可测性
title: ≤30 字
quote: PRD 原文逐字引用（≤60 字）
section: 章节号或标题
issue: 为什么必须改
suggestion: 补成什么样（可直接抄进 PRD 的一段表述）
```

**不要**输出「建议补充异常处理」这种没有具体动作的结论。写不出具体建议的，就别报。
