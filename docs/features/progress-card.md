# 功能简报：过程卡（思考流 + 答案同卡）

> 改这个功能前读这一页即可动手。与代码矛盾时以代码为准，并回写本页。

## 1. 一句话

用户 @bot 提一个问题，得到**一条**消息：顶部一句结论，展开可看「我为什么这么想、
调了哪几步」，下面就是答案。

## 2. 主链路

```
dsh 内核 (ACP)
  → adapter._translate_update：agent_thought_chunk → TextChunkEvent(THOUGHT)
  → gateway.DshGateway.on_event：thought 帧 → on_event("thought", 文本)；
                                 tool_call 帧 → action_of(title) → on_event(stage, 动作)
  → main._on_progress：timeline.observe(stage, detail) 按到达顺序合并
  → main._heartbeat（每 5s 无条件重画一次，只更新计时）
  → main._push_card（节流 2s，终态必刷）
      → progress_card.build_running：⏳ + 展开的过程面板 + 已处理 Ns · 预估
  → 答复就绪 → build_done：✅ + 答案首句做标题 + 收起的过程面板 + 答案 + 反馈按钮
```

## 3. 期望行为（可观察面）

- 运行中：卡片头是「⏳ 正在处理：{用户问题}」，下面是展开的过程面板，
  思考段落与「· 加载能力说明 ✓」这类动作按**发生顺序**交错出现，但**只留最近
  3 块 / 思考每块 200 字**——运行中的卡只值「此刻在干什么」，整轮积累铺开是
  一屏读不完的推理。
- 完成：同一张卡刷成绿头，标题是答案的首句（不是「已完成」），过程面板**收起**，
  答案直接跟在下面；👍/👎 按钮在同一张卡里。过程面板在**动作少于 2 步时不渲染**
  （「处理过程 · 1 步」既不解释任何东西，又占掉答案前面的位置）。
- 全程只有一条消息：答复不再单独发文本（答复不是可复制的文本消息是已知代价）。
- 答复超过 8000 字：过程卡照常收尾，正文退回文本消息（卡片塞不下会被整卡拒绝）。
- 秒回链路（direct/help/clarify）：不发卡，照旧表情回执 + 文本回复。

## 4. 约束与不变量（改前必读）

- **思考只来自 dsh 的 thought 帧**，不要拿工具名或模型正文冒充「思考」
  （证据：`tests/test_progress_card.py::test_gateway_forwards_thought_chunks`）。
- **相邻 thought 帧必须续写同一块**：dsh 把一段推理切成几十帧，逐帧成块会让卡片
  变成碎句墙（证据：`test_consecutive_thought_frames_merge_into_one_block`）。
- **失败动作行必须保留**，重试另起一块：用户要知道哪一步没成
  （证据：`test_failed_action_keeps_its_line_when_retried`）。
- **卡片发送必须串行**：`_on_progress` 每帧投成独立任务，两帧几乎同时到达时
  会双双看到「还没有 card_id」各发一张卡，那一轮就多出一条永远停在「正在处理」
  的孤儿卡。检查与发送在同一把 `_card_lock` 里（`app/main.py::_push_card`）。
- **整轮必须同一条事件循环**：`lark_channel` 在自己起的后台线程 + 独立循环上
  await 我们注册的 handler，而 dsh 的进度帧从主循环推来——两边抢同一把
  `_card_lock` 时会抛 `is bound to a different event loop`，异常从完成卡那次
  刷新冒出去，**把已经拿到的答案整条丢掉**（线上实测 3 次）。所以 `BotChannel`
  注册时记下本仓循环、回调统一投回（`tests/test_channel_loop.py` 钉住）。
- **锁的获取也在 try 里**：刷新失败只能让过程卡降级（`_progress_state["cancelled"]`），
  绝不能连答案一起丢——`_push_card` 的 `async with` 必须在异常兜底内。
- **运行态与完成态用不同预算**：`Timeline.to_markdown()` 的默认值给完成态
  （12 块 / 5000 字），运行态传 `_RUNNING_*` 覆盖。别再让运行态吃默认值。
- **超预算按整块丢头，不做字符截断**：字符截断会把最新一段思考的开头切掉，
  用户读到逻辑接不上的半句话。单块内部才按尾部裁剪。
- **表格不能直接塞 markdown**：飞书卡片 markdown 不吃 GFM 管道表格语法，
  会渲染成原始竖线；必须转原生 `table` 组件（`progress_card._answer_elements`）。
- **不改**：`narrative.action_of` 的「认识就翻译、不认识就退回原名」策略——
  把 grep 说成「查询数据库」比显示 grep 更糟。
- **不改**：答复 ≤8000 字这个门限的用途是「别让卡片因体积被整卡拒绝」，
  调大前先用真实长答复试发。
- **耗时行必须持续走**：静默期不刷新，用户看到的就是「卡死」。`_heartbeat`
  每 5s 重画（飞书卡片编辑限频约 5 次/秒，5s 安全），且必须走 `force=False`
  的节流路径，否则事件密集时会翻倍刷新。
- **预估只升不降**：按「已走到第几步」取档位（15/60/180/300s），窗口一过
  就写「已超，仍在处理」。报得很准会被当承诺，预估变短会被当倒退。

## 5. 单源与派生物

- 单源：`app/dsh/timeline.py`（合并规则与预算）、`app/dsh/progress_card.py`（渲染）、
  `app/dsh/narrative.py`（工具名→动作文案）、`app/dsh/gateway.py::on_event`（事件分流）、
  `app/main.py::{_push_card,_running_card,_done_card}`（接线与节流）
- 派生物：无

## 7. 已知坑

- dsh 的思考是**英文**（模型内部推理语言），用户在中文群里看到英文段落。
  要中文就得在路由提示词里要求「思考用中文」，那是行为改动，需单独确认。
- 单块思考上限 900 字、整条 5000 字、块数 12：这几个数决定卡片体积，
  调大前先在真实群发一张看飞书是否接受。
- 卡片正文不可选中复制（文本消息可以）。用户若抱怨复制不了答案，
  把答复改回文本、只留过程卡是唯一解——那是产品取舍，不是 bug。
